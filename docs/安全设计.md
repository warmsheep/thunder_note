# 安全设计

## 文档定位
本文档记录闪记当前与近期需要遵循的安全设计约束，重点覆盖认证、权限、密码、文件上传、配置项安全与后续扩展边界。

## 当前认证与权限事实
- 当前后端使用 JWT + Spring Security 无状态认证
- 公开路径：`/api/auth/**` 与 `/actuator/health`
- 其他接口默认要求认证
- Android 端 token 通过 `TokenManager` 使用加密存储保存

## JWT 设计
- access token 与 refresh token 并存
- 当前配置来源：`application.yml`
  - `access-expiration: 3600000`
  - `refresh-expiration: 604800000`
- refresh token 当前由后端服务管理

## 密码与账号规则
- 当前注册校验：
  - `username` 长度 3-32
  - `email` 必须符合邮箱格式
  - `password` 长度 6-128
- 当前密码编码：BCrypt

## 文件上传安全
- 当前单文件大小限制：20MB
- 当前请求总大小限制：20MB
- 当前文件接口已存在，但仍缺明确的类型白名单、病毒检查、对象名治理

## 当前安全缺口
- JWT secret 当前仍是本地示例式配置，不适合作为生产配置
- 缺少接口频率限制策略
- 缺少上传文件类型白名单策略
- 缺少更细的权限角色体系
- 缺少安全审计日志文档

## 近期安全任务
- 统一 token 过期与刷新策略
- 统一 Android token 失效后的回退逻辑
- 为上传接口补类型/大小/错误语义说明
- 为登录、刷新、登出补最小测试覆盖

## 维护规则
- 认证、权限、token 生命周期、密码规则发生变化时，必须同步更新本文件
- 涉及安全策略的配置项不能只改代码不改文档
