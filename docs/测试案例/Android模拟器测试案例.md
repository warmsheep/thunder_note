# Android 模拟器测试案例

## 1. 文档定位
- 本文档用于 Thunder Note Android Java 客户端在 **Android 模拟器 + 真实后端** 条件下的手工测试计划与测试案例沉淀。
- 测试范围以当前真实实现为准，优先覆盖 `auth / flashnote / chat / collection / favorite / profile / settings` 主链。
- 文档同时记录：测试前置条件、测试步骤、预期结果、异常流、边界流，以及本轮实际执行结果。

## 2. 事实依据
- Android 客户端主模块：`thunder-note-android/`
- 应用包名：`com.flashnote.java`
- 启动入口：`thunder-note-android/app/src/main/AndroidManifest.xml`
- 主导航宿主：`thunder-note-android/app/src/main/java/com/flashnote/java/MainActivity.java`
- 主壳层：`thunder-note-android/app/src/main/java/com/flashnote/java/ui/main/MainShellFragment.java`
- 当前模块范围参考：
  - `thunder-note-android/README.md`
  - `docs/Android客户端Java重启基线.md`
  - `docs/完整开发计划.md`

## 3. 当前测试范围

### 3.1 本轮优先测试范围（P0）
1. 启动与认证主线：Splash、Login、Register、Logout
2. 主壳层与底部 Tab：FlashNote、Collection、Favorite、Profile
3. 闪记主线：列表加载、进入聊天、新建/编辑/删除
4. 聊天主线：消息列表、发送文本、失败反馈、返回链路
5. 资料与设置：资料展示、设置入口、服务地址、退出登录

### 3.2 次级测试范围（P1）
1. 收藏列表浏览与从收藏回跳聊天
2. 联系人与联系人聊天
3. 手动同步入口
4. 文件/媒体入口的基础可用性

### 3.3 本轮暂不深测范围
1. 完整离线恢复链
2. 多媒体消息全矩阵
3. 复杂同步冲突场景
4. 真机专属权限/系统行为差异

## 4. 测试环境与前置条件

### 4.1 环境要求
- Android 模拟器通过 `adb connect` 可连接
- 后端服务已启动，并且 **模拟器网络可访问后端地址**
- 当前 debug 包默认地址：`http://192.168.3.7:8080/`
- 测试账号：由实际环境提供；本轮已使用 `root / 111111`

### 4.2 测试基线检查清单
- [ ] 模拟器在线：`adb devices -l` 可见目标设备
- [ ] App 可安装并启动
- [ ] Splash 可正常进入 Login 或 MainShell
- [ ] 模拟器可访问后端地址
- [ ] 登录接口可返回成功或明确错误

## 5. 执行策略
- 先测 **正常主链**，保证产品最短可用路径可跑通。
- 再测 **异常流**，确认错误提示、回退与状态恢复是否合理。
- 最后测 **边界流**，覆盖空输入、重复操作、状态切换、冷启动等高频风险点。
- 每条案例记录：编号、优先级、前置条件、步骤、预期结果、实际结果、状态。

## 6. 测试案例

### 6.1 启动与认证

#### TC-AUTH-001 启动后未登录进入登录页
- 优先级：P0
- 类型：正常流程
- 前置条件：清空 App 数据，设备网络正常
- 步骤：
  1. 安装并启动 App
  2. 等待 Splash 结束
- 预期结果：进入登录页，展示用户名、密码输入框与登录按钮

#### TC-AUTH-002 使用有效账号密码登录成功
- 优先级：P0
- 类型：正常流程
- 前置条件：后端服务可达，测试账号有效
- 步骤：
  1. 在登录页输入正确用户名和密码
  2. 点击“登录”
- 预期结果：登录成功，进入 MainShell，登录态持久化

#### TC-AUTH-003 使用错误密码登录失败
- 优先级：P0
- 类型：异常流程
- 前置条件：存在有效用户名
- 步骤：
  1. 输入正确用户名、错误密码
  2. 点击“登录”
- 预期结果：停留在登录页，显示明确错误信息，按钮恢复可点击

#### TC-AUTH-004 用户名为空时阻止提交
- 优先级：P0
- 类型：边界测试
- 前置条件：位于登录页
- 步骤：
  1. 用户名留空
  2. 输入任意密码
  3. 点击“登录”
- 预期结果：不进入主页面，给出输入校验提示或阻止请求发送

#### TC-AUTH-005 密码为空时阻止提交
- 优先级：P0
- 类型：边界测试
- 前置条件：位于登录页
- 步骤：
  1. 输入用户名
  2. 密码留空
  3. 点击“登录”
- 预期结果：不进入主页面，给出输入校验提示或阻止请求发送

#### TC-AUTH-006 网络不可达时登录失败反馈
- 优先级：P0
- 类型：异常流程
- 前置条件：后端地址不可达或服务关闭
- 步骤：
  1. 输入有效账号密码
  2. 点击“登录”
- 预期结果：界面应给出失败反馈，不应长期停留“登录中...”且无结果

#### TC-AUTH-007 登录成功后冷启动自动进入主壳
- 优先级：P1
- 类型：正常流程
- 前置条件：已成功登录
- 步骤：
  1. 退出 App
  2. 重新启动 App
- 预期结果：Splash 后直接进入 MainShell 或手势解锁页（若启用）

#### TC-AUTH-008 退出登录后回到登录页
- 优先级：P0
- 类型：正常流程
- 前置条件：已登录进入主壳
- 步骤：
  1. 进入 Profile / Settings
  2. 执行退出登录
- 预期结果：返回登录页，旧 token 失效
