# 闪记完整开发计划

## 文档定位
本文档是闪记项目后续开发工作的总计划文档，用于长期维护整个项目从 **MVP → 增强版 → 完整项目 → 远期扩展** 的推进路线。所有开发任务、模块边界、接口级 TODO、阶段依赖与验收口径，后续都以本文件为主维护。

本文档严格区分四类信息：
- **当前已实现**：代码中已存在并可核对
- **当前部分实现**：代码中已有骨架或局部能力，但未形成闭环
- **当前主线必补**：为了形成可用产品主线，必须尽快完成
- **目标态规划**：方向已明确，但不属于当前主线交付范围

## 计划使用规则
- 每个任务都应尽量标注：**状态**、**来源**、**依赖**、**验收出口**。
- 事实来源优先级遵循根目录 `AGENTS.md`：代码/迁移脚本 > 当前态文档 > 目标态文档 > HTML 原型。
- 如果某条 TODO 会影响接口、数据结构、跨端行为，必须先补充“当前事实”再推进开发。
- 当前主线只围绕 **Spring Boot 后端 + Android 客户端**，Web / iOS / admin 一律放到远期阶段。
- 本文档是唯一执行型 backlog；`TODO事项.md` 只作为路线图摘要，不再与本文件并行维护详细执行优先级。

## 一、项目目标

### 1.1 产品目标
闪记希望提供一套围绕“短笔记 + 对话消息 + 合集整理 + 多端同步”展开的个人知识记录体验。最终目标不是单一笔记应用，而是一个支持多端协同、内容沉淀、轻量沟通式记录与结构化整理的知识管理产品。

### 1.2 当前现实
当前仓库真实落地内容包括：
- Spring Boot 后端
- Android Java 客户端（当前主模块）
- HTML 原型
- 中文设计与规划文档

当前尚未落地代码的部分包括：
- Web 用户端
- iOS 客户端
- 管理后台
- 搜索、收藏、完整同步协议、完整多媒体消息体系

### 1.3 当前总原则
当前阶段是"在 Java 客户端已经接管主模块的前提下，继续补齐核心页面、数据链路和后端真实联调"。后端仍继续作为真实事实来源。

### 1.4 Android 客户端决策
- Android 当前 `thunder-note-android/` 为 **Java 客户端主模块**。

## 二、开发阶段总览

## 阶段 A：MVP（后端稳定 + Android Java 客户端补齐）
目标：在现有 Java Android 客户端基础上补齐核心页面、后端真实链路和主要交互闭环，让新主线从“可编译壳层”进入“可持续开发主链”。

### MVP 验收口径
- Java 客户端已稳定构建并成为仓库唯一 Android 主模块
- Auth / FlashNote / Chat 具备可运行主链，不再只是静态页面壳层
- Collection / Favorite / Profile 的页面、数据来源与成熟度有明确状态说明
- Android ↔ 后端新的执行型联调基线开始以 Java 客户端为准持续维护

### MVP 进入条件
- 当前态文档已经完成与代码事实对齐
- 历史漂移（`/api/v1`、邮箱登录、MySQL、未落地端）已在文档中显式标记

### MVP 完成检查清单（Definition of Done）
- [x] 已明确哪些知识必须继承到 Java 客户端：接口事实、产品页面范围、本地能力边界、经验库问题
- [x] `docs/完整开发计划.md`、`TODO事项.md`、`客户端架构设计.md`、`架构设计.md`、`技术栈选型.md`、`开发测试部署经验库.md` 已同步回写

### MVP 阶段出口
- 只有当上面的完成检查清单全部满足，才允许进入增强版阶段。

## 阶段 B：增强版（主线能力补齐）
目标：补齐收藏、文件闭环、多媒体消息基础链路、同步可靠性、用户体验完善。

### 增强版进入条件
- MVP 阶段出口已满足
- 当前主线数据模型与接口契约已稳定，不再频繁重命名或改语义

### 增强版阶段出口
- 收藏能力具备完整后端 + Android 真实链路
- 文件链路具备基础元数据治理与稳定错误处理
- 多媒体消息至少完成一类真实扩展能力（建议图片）
- 同步具备基础重试、待同步队列、失败场景处理
- 核心主线拥有最小可用测试与联调检查清单

## 阶段 C：完整项目（产品能力完善）
目标：补齐搜索、完整同步协议、系统信息、更多内容组织能力，并把文档、测试、运维能力拉齐。

### 完整项目进入条件
- 增强版阶段出口已满足
- auth / flashnote / message / collection / file / sync 主线已经稳定，不再依赖大量模拟数据

### 完整项目阶段出口
- 搜索、完整同步协议、系统与诊断能力均有真实实现与文档支撑
- 工程化、测试、发布与运维文档形成可执行体系
- 当前态与目标态文档分界清晰，阶段内无重大漂移未处理

## 阶段 D：远期扩展（多端与后台）
目标：推进 Web、iOS、管理后台，以及更高级的搜索、内容治理、系统运营能力。

### 远期扩展进入条件
- 完整项目阶段出口已满足
- 当前后端 API 契约与核心数据模型已足够稳定，可被新端复用

### 远期扩展阶段出口
- Web / iOS / admin 至少具备独立规划、独立任务分解与与当前主线对齐的数据契约

## 十二、持续维护规则

- 后续新增任务时，先判断其属于哪个阶段，再补到对应模块下。
- 如果某项任务细化到可以独立开发，优先在本文件中追加“接口级 TODO”而不是散落在别处。
- 如果设计变更会影响范围、模型、接口或阶段顺序，必须同步更新本文件。
- 当某项能力真正落地后，应把它从“目标态/待办”移动到“当前已实现/当前部分实现”。
- 如果后续需要更细的执行层拆分，可在本文件基础上再派生迭代计划，但本文件始终是总计划源头。
