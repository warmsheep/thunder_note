# 技术栈选型

## 文档定位
本文档记录闪记项目的技术选型。需要注意：其中一部分已经在当前仓库实现，另一部分仍属于未来规划。

## iOS 客户端选型说明
> 状态：未落地工程，仅 `thunder_note_ios/` 仓库基线。以下为目标态约定，建立 Xcode 工程时必须按本节执行；偏离需先回写本文件。

### 语言与最低系统
- **语言**：Swift 5.10+，禁止 Objective-C，新代码默认使用 `async / await`、`Sendable`、`actor` 等新并发语义。
- **目标平台**：iOS 16.0+（与当前 Android `minSdk` 对齐的最近上一代主流 LTS）。后续如要降级到 iOS 15，必须先评估 `Observation`、`NavigationStack`、`PhotosPicker`、`AsyncImage` 等 API 的回退方案。
- **架构**：仅打 arm64，模拟器同时支持 x86_64 / arm64。
- **构建工具**：Xcode 15.4+，命令行 `xcodebuild`；CI 默认走 `xcodebuild -scheme ThunderNote -destination 'platform=iOS Simulator,name=iPhone 15' test`。

### UI 与状态
- **UI 框架**：SwiftUI 为主；不可避的系统级能力（`UIDocumentPickerViewController`、`AVPictureInPictureController`、系统分享扩展等）通过 `UIViewControllerRepresentable` 包装回 SwiftUI。
- **导航**：`NavigationStack` + 类型化路由值，禁止再用 `NavigationView` / `NavigationLink(isActive:)`。
- **状态管理**：`@Observable` 宏（iOS 17+）+ 依赖注入容器；iOS 16 兼容期使用 `ObservableObject` + `@Published`。一个屏幕对应一个 `ViewModel`（class，`@MainActor` 标注）。
- **样式**：统一在 `DesignTokens`（颜色 / 字号 / 圆角 / 间距）中维护，与 Android `colors.xml` 和 Web `--color-*` token 保持等价；图标走 SF Symbols 或资产目录里的矢量素材，禁止使用 PNG emoji 作为导航图标。

### 网络与协议
- **HTTP 客户端**：`URLSession` + 自定义 `APIClient`（拦截器：注入 `Authorization`、统一 `ApiResponse<T>` 解包、401 自动 refresh）。
- **序列化**：`Codable` + `JSONDecoder.dateDecodingStrategy = .iso8601`，与后端 `LocalDateTime` ISO 字符串对齐。
- **实时通道**：`URLSession` 自管 SSE（`EventStreamParser`），不引入第三方库；目标态可由 `AsyncThrowingStream<ServerEvent, Error>` 暴露。
- **媒体上传**：`URLSession` `uploadTask(with:fromFile:)`，文件大小阈值与 Android `FileRepositoryImpl` 对齐。

### 本地持久化
- **结构化数据**：iOS 17+ 用 SwiftData，iOS 16 fallback 到 Core Data；表结构与 Android Room（`flash_notes_local` / `collections_local` / `messages_local` / `favorites_local` / `pending_messages`）一一对应。
- **键值与安全**：
  - 普通设置：`UserDefaults` + 自封装 `@AppStorage` 扩展。
  - Token / Refresh Token / 手势锁密文：Keychain（`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`），不进入 iCloud Keychain。
  - 服务器地址（官方 / 自托管）：与 Android `ServerConfigStore` 对齐，单站冷切换语义。
- **媒体缓存**：`FileManager` + 自管 LRU；图片复用 `NSCache<NSString, UIImage>`，避免引入 SDWebImage / Kingfisher 直到确有需求。

### 并发与后台
- **并发模型**：Swift Concurrency；ViewModel 走 `@MainActor`，仓储层走自定义 `actor`。
- **后台任务**：用 `BGTaskScheduler` 注册同步任务（与 Android `WorkManager`/`SyncRepositoryImpl` 等价），处理后台 pull / 重试 push。
- **生命周期解锁**：手势锁触发时机参考 Android `GestureUnlockPromptFragment`，使用 `ScenePhase` 监听冷启动 / 回前台超时。

### 依赖管理与三方库
- **依赖管理**：默认 Swift Package Manager；只有 SPM 完全无法满足时才考虑 CocoaPods，且必须在本文件登记。
- **三方库白名单（首次）**：
  - 媒体：`AVKit`、`PhotosUI`（系统库，无外部依赖）
  - PDF / 文件预览：`PDFKit`、`QuickLook`（系统库）
  - 录音 / 波形：`AVFoundation`（系统库）+ 自实现 `VoiceWaveView` 等价
  - 日志：`os.Logger`（系统库），与 Android `DebugLog` 等价
- **明确禁止**：Alamofire、Moya、RxSwift、Realm 等第三方栈，除非新建任务并回写本文件。

### 测试
- **单元测试**：XCTest；ViewModel、Repository、API 客户端、Codable mapping 必测。
- **UI 测试**：XCUITest 守关键主流程（登录 / 闪记列表 / 会话发送）。
- **网络契约测试**：基于固定 JSON fixture + `URLProtocol` mock，与 Android `当前联调契约总表.md` 同源。
- **覆盖率目标**：业务核心层（Repository / API）≥ 70%。

### 构建与发布
- **签名**：开发期手动签名，CI 阶段走 fastlane match（与 CI 落地一起决策，当前不引入）。
- **打包**：Release 走 `xcodebuild archive` + `exportArchive` 生成 IPA；TestFlight 通道暂未规划。
- **版本号**：`CFBundleShortVersionString` 与 Android `versionName` 对齐，`CFBundleVersion` 单调递增。

## 关键决策
### PostgreSQL 取代 MySQL
- 当前仓库真实数据库已经是 PostgreSQL
- 旧文档中出现的 MySQL 描述均应视为过时内容
- 数据库事实以 `application.yml` 与 Flyway 迁移为准

### Vue 取代 React
- Web 用户端 v1 已冻结为 Vue 3 + Vite + Pinia，并落在 `thunder_note_server/frontend/`
- 旧文档里出现的 React/Zustand 方案视为已淘汰方案
- 后续 Web 技术栈若再变更，必须同步更新本文件、`架构设计.md` 与 `客户端架构设计.md`

### SSE 取代 WebSocket
- 当前同步与实时提示的目标方向是 SSE
- 旧文档中若仍出现 WebSocket 长连接，应视为过时设计

## 维护规则
- 涉及当前实现的技术结论，必须能在代码或配置中找到证据
- 涉及 Web / iOS / Admin 的选型，必须明确标注选型状态、代码归属和实现状态
- Web 端如引入 Node/Vite 构建链，必须说明其与后端 Maven 构建、静态资源托管和部署 jar 的关系
- 如果未来技术栈变更，应优先更新本文件，再同步到架构和客户端文档
