# 数据同步协议设计

## 文档定位
本文档描述**目标态同步设计**，不是当前代码的完整实现说明。当前真实实现仅具备轻量的 `bootstrap / pull / push` 基础接口。

## 当前实现现状
### 后端当前已有
- `/api/sync/bootstrap`
- `/api/sync/pull`
- `/api/sync/push`

### Android 当前现状
- 同步接口声明已存在
- `SyncRepositoryImpl` 仍为空骨架
- 尚未形成完整的离线变更回放与冲突处理体系

## 当前最小返回结构
### bootstrap / pull
当前后端 `SyncServiceImpl` 返回的结构核心包含：
```json
{
  "profile": {},
  "notes": [],
  "collections": [],
  "messages": [],
  "favorites": [],
  "serverTime": "2026-03-13T00:00:00Z"
}
```

其中 `bootstrap` 会额外返回：
```json
{
  "bootstrap": true
}
```

### push
当前后端 `push` 的返回结构核心包含：
```json
{
  "accepted": true,
  "processed": {
    "notes": 0,
    "collections": 0,
    "messages": 0,
    "favorites": 0
  },
  "serverTime": "2026-03-13T00:00:00Z",
  "username": "alice"
}
```

## 当前最小 payload 约定
当前代码并没有严格 payload schema，MVP 阶段建议最小统一为：
```json
{
  "notes": [],
  "collections": [],
  "messages": [],
  "favorites": []
}
```

说明：
- 当前后端已能处理 `notes / collections / messages / favorites` 这四类最小 payload
- Android 当前主链已把 `favorites` 纳入 push payload，但仍未形成完整离线同步与删除回放策略

## 当前同步流程（MVP）
1. Android 启动后可调用 `bootstrap` 获取初始 profile / notes / collections / messages / favorites
2. 本地存在待同步变更时，调用 `push`
3. Android 需要刷新远端状态时，调用 `pull`
4. 当前不具备完整冲突解决，只能先做最小同步闭环

## 当前已知协议缺口
- 没有正式版本号字段
- 没有正式游标字段
- 没有客户端操作唯一标识
- 没有冲突返回结构
- 没有错误重试语义
- 没有文件/复杂消息的统一同步对象定义
- 没有 `Last-Event-ID` 类重连续传约定

## 目标态设计范围
- 多端数据同步（Android / Web / iOS）
- 离线写入与恢复后推送
- 变更拉取与冲突处理
- 服务端版本推进
- SSE 提示通道

## SSE 事件格式（目标态）
如果后续同步或消息通知统一走 SSE，建议事件结构约定为：
```text
event: sync
data: {"op":"UPDATE","entity":"note","id":"123","payload":{}}
id: 12345
retry: 5000

```

字段建议：
- `event`：事件类型，如 `sync`、`message`、`heartbeat`、`conflict`
- `data`：JSON 负载
- `id`：事件序号或游标，用于断线重连后续传
- `retry`：客户端建议重连等待时间（毫秒）

说明：
- SSE 是单向通道，只负责服务端向客户端推送事件
- 客户端写操作仍通过普通 HTTP 接口完成

## 当前未实现的关键点
- 完整的客户端操作幂等去重
- 完整冲突检测与解决策略
- 完整版本号 / 游标体系
- Android 端真实同步执行器
- 与更复杂 schema 相匹配的同步对象模型

## 使用规则
- 讨论“当前同步为什么没生效”时，不要直接引用本文件当成现状说明
- 实现同步功能时，应先确认当前后端 schema、controller、Android repository 是否已补齐
- 如果未来 sync 真正落地，应新增“当前同步实现说明”，不要把目标态协议直接改写成现状
- 如果后端或 Android 开始收敛真实 payload 结构，必须第一时间更新本文件
