# 闪记需求分析

## 文档定位
本文档描述闪记的产品目标，并明确区分：**当前已实现**、**已规划未实现**、**仅原型验证**。涉及技术事实时，以代码与当前态设计文档为准。

## 产品目标
闪记希望提供一套围绕"短笔记 + 对话消息 + 合集整理 + 多端同步"展开的个人知识记录体验。当前仓库已经落地后端、Android Java 客户端初版、Web 用户端 v1，并用 HTML 原型验证了部分 UI/交互方向。

## 当前范围
### 已有实现基础
- Spring Boot 后端，包含认证、用户资料、闪记、消息、合集、文件、同步等基础模块
- Android Java 客户端，已具备 Splash / Login / Register / Main / FlashNote / Chat 主壳层
- HTML 原型，覆盖登录、主页、消息、多媒体、个人中心、设置等交互探索

### 当前未落地但仍是目标
- iOS 客户端：`thunder_note_ios/` 独立 Git 目录已创建，但当前仅有 `LICENSE`，尚无可运行客户端工程和业务实现
- 管理后台
- 搜索、收藏、系统信息等扩展能力
- 完整离线同步协议与冲突处理

## 当前用户流程
### 登录与进入应用
- 用户通过用户名 + 密码登录
- 当前 Java Android 客户端通过 `TokenManager` 保存登录态
- 当前 Java Android 客户端首次进入通常经过 Splash → Login/Register → Main/Chat 导航

### 内容操作
- 用户可管理闪记、消息、合集等基础内容
- 当前 Java Android 客户端已完成 auth / flashnote / message / collection 主链，并提供 sync / file 最小操作入口
- 当前 MVP 下，一条闪记最多属于一个合集；归属为空时展示为“未分类”
- 多媒体消息、搜索等仍属于目标态需求；收藏已提供基础消息收藏闭环

## Android 当前状态说明
- 当前 Android 主模块是 Java 客户端。
- 与 Android 相关的历史能力描述，不能自动等同于当前 Java 客户端已经完整具备这些能力。

## 设计与实现差异
- 历史文档长期按"邮箱登录"描述，但当前实现是"用户名登录"
- 历史文档默认存在 Web、iOS、管理后台。当前 **Web v1 已落地**（D1 阶段）；iOS 仅创建了 `thunder_note_ios/` 独立 Git 目录，尚无客户端工程；管理后台仍无代码实现
- 历史文档对同步、搜索、收藏、消息类型的描述大多是目标态，不是当前交付范围

## 后续需求维护规则
- 需求文档用于描述产品目标，不强行降级到"只写现状"
- 但每个核心能力都必须标注状态：`当前已实现基础`、`计划中`、`仅原型验证`
- 当需求与代码冲突时，应先修正文档状态说明，再决定是否补实现
- `当前已实现基础` 只表示后端或客户端某一侧已有基础能力，不等于 Android ↔ 后端端到端闭环已完成；闭环判断以 `当前联调契约总表.md` 与真实代码为准
