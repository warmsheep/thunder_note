# 数据库设计

## 文档定位
本文档只描述**当前真实数据库结构**。数据库事实以 PostgreSQL 配置与 Flyway 迁移脚本为准，不再沿用旧的 MySQL 设计稿。

## 当前数据库
- 数据库类型：PostgreSQL
- 迁移方式：Flyway
- 事实来源：`thunder-note-server/src/main/resources/db/migration/V1__initial_schema.sql`

## 当前关系与约束
- `users.username`：唯一
- `users.email`：唯一
- `user_profiles.user_id`：唯一，外键指向 `users.id`，删除用户时级联删除
- `flash_notes.user_id`：外键指向 `users.id`，删除用户时级联删除
- `messages.sender_id`：外键指向 `users.id`，删除用户时级联删除
- `messages.receiver_id`：外键指向 `users.id`，删除用户时级联删除
- `note_collections.user_id`：外键指向 `users.id`，删除用户时级联删除
- `favorite_messages.user_id`：外键指向 `users.id`，删除用户时级联删除
- `favorite_messages.message_id`：外键指向 `messages.id`，删除消息时级联删除

## 当前删除与约束说明
- `flash_notes` 使用 `is_deleted` 作为逻辑删除字段
- `user_profiles.user_id` 通过唯一约束确保一个用户只有一份资料
- `messages` 当前没有额外会话表，消息直接挂在 sender / receiver 上，并通过 `flash_note_id` 承接闪记内对话归属
- `note_collections` 当前没有合集与闪记的关联中间表；当前 Android MVP 通过 `flash_notes.tags` 承接单一合集名称归属

## 当前表结构
### 1. `users`
核心用户表，包含：
- `id`
- `username`
- `email`
- `password`
- `nickname`
- `avatar`
- `status`
- `created_at`
- `updated_at`

约束：
- `username NOT NULL UNIQUE`
- `email NOT NULL UNIQUE`
- `password NOT NULL`
- `status NOT NULL DEFAULT 1`

### 2. `user_profiles`
用户资料扩展表，包含：
- `id`
- `user_id`
- `bio`
- `preferences_json`
- `created_at`
- `updated_at`

约束：
- `user_id NOT NULL UNIQUE`
- 外键：`user_id -> users.id`

### 3. `flash_notes`
闪记主表，包含：
- `id`
- `user_id`
- `title`
- `icon`
- `content`
- `tags`
- `is_deleted`
- `created_at`
- `updated_at`

约束：
- `user_id NOT NULL`
- `is_deleted NOT NULL DEFAULT FALSE`
- 外键：`user_id -> users.id`

当前字段语义补充：
- `title`：闪记名称
- `icon`：闪记图标（emoji）
- `tags`：当前 MVP 只承接单一合集/分类名称，不是通用多标签系统

### 4. `messages`
消息表，包含：
- `id`
- `sender_id`
- `receiver_id`
- `content`
- `read_status`
- `flash_note_id`
- `role`
- `created_at`
- `media_type`
- `media_url`
- `media_duration`
- `thumbnail_url`
- `file_name`
- `file_size`
- `payload` (当前已实现：JSONB 格式，用于存储卡片消息等复合结构)

约束：
- `sender_id NOT NULL`
- `receiver_id NOT NULL`
- `content NOT NULL`
- `read_status NOT NULL DEFAULT FALSE`
- 外键：`sender_id -> users.id`
- 外键：`receiver_id -> users.id`

### 5. `note_collections`
合集表，包含：
- `id`
- `user_id`
- `name`
- `description`
- `created_at`
- `updated_at`

约束：
- `user_id NOT NULL`
- `name NOT NULL`
- 外键：`user_id -> users.id`

当前使用说明：
- `note_collections` 主要作为合集目录
- 闪记是否属于某个合集，当前不靠关系表，而是由 `flash_notes.tags = note_collections.name` 的约定承接
- 合集重命名时需要同步更新对应 `flash_notes.tags`；删除合集时需要把对应闪记归属清空

### 6. `favorite_messages`
收藏消息表，包含：
- `id`
- `user_id`
- `message_id`
- `created_at`

约束：
- `user_id NOT NULL`
- `message_id NOT NULL`
- 唯一约束：`(user_id, message_id)`
- 外键：`user_id -> users.id`
- 外键：`message_id -> messages.id`

## 当前索引
- `idx_flash_notes_user_id`
- `idx_messages_sender_id`
- `idx_messages_receiver_id`
- `idx_messages_flash_note_id`
- `idx_note_collections_user_id`
- `idx_favorite_messages_user_id`
- `idx_favorite_messages_message_id`

## 当前数据库限制与缺口
- 当前 schema 仍偏 MVP，没有 files 元数据表、devices、sync_logs 等实体表
- 当前没有消息附件表、会话表、合集-闪记关系表
- 当前逻辑删除只在 `flash_notes` 上明确存在

## 当前缺失但历史设计里存在的对象
以下内容在旧数据库设计文档中出现过，但当前真实迁移脚本尚未实现：
- 文件表
- 更复杂的跨类型收藏表（如闪记/消息统一收藏模型）
- 邮箱验证码表
- 设备表
- 同步日志/客户端操作表
- 更复杂的消息类型与附件模型

## 维护规则
- 任何数据库事实变更，先改 Flyway，再更新本文件
- 如果未来要重新引入更复杂的数据模型，应新开“目标态数据库设计”，不要再把旧 MySQL 方案混回当前态文档
- 新增外键、唯一约束、索引、逻辑删除字段时，必须同步补进本文件
