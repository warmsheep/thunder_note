# 文档目录知识库

## 概览
`docs/` 里的文档分三类：当前态文档、目标态设计文档、历史/运维文档。读文档前先判断它属于哪一类，避免把目标态误当成已实现。

## 高频入口
| 需求 | 文件 | 说明 |
|------|------|------|
| 开发主计划 | `完整开发计划.md` | 后续开发任务的总计划源头，先看阶段、依赖、接口级 TODO |
| Android 重启基线 | `Android客户端Java重启基线.md` | 查看 Java 重启背景、历史冻结事实和当前实现边界 |
| 经验沉淀 | `开发测试部署经验库.md` | 开发、测试、部署前先看这里，避免重复踩坑 |
| 当前联调契约 | `当前联调契约总表.md` | 客户端与后端的历史契约参考 |
| 产品范围 | `需求分析.md` | 产品目标 + 当前/计划状态 |
| 当前架构 | `架构设计.md` | 当前态与目标态并列说明 |
| 当前 API | `API接口设计.md` | 当前实现优先 |
| 当前数据库 | `数据库设计.md` | 以 PostgreSQL + Flyway 为准 |
| 客户端现状 | `客户端架构设计.md` | 当前 Android + 未来多端 |
| 同步设计 | `数据同步协议设计.md` | 目标态设计，当前实现较轻 |
| 视觉规范 | `页面设计规范.md` | 原型与 Android 的视觉约束 |

## 使用规则
- 文档语言与沟通规则遵循根目录 `AGENTS.md`。
- 开发类新会话默认先看 `完整开发计划.md`，再进入具体模块文档。
- 开发、测试、构建、部署类任务默认补读 `开发测试部署经验库.md`。
- Android ↔ 后端联调任务，若需要理解历史漂移先看 `当前联调契约总表.md`；若任务针对当前 Java 客户端实现，先看 `Android客户端Java重启基线.md` 与当前代码，再决定哪些历史契约仍有参考价值。
- 文档不能直接等同于实现；冲突时先核对代码，再决定是否修文档。
- 更新文档时，优先补“当前实现状态”而不是抹掉旧设计痕迹。
- 明显领先实现的文档要明确标注“目标态”或“当前未完全实现”。
- 每完成一个阶段或一个关键模块，都应优先回写 `完整开发计划.md`，再回写对应当前态文档。
- 每次遇到可复用的真实问题、故障和解决方式，都应回写 `开发测试部署经验库.md`。

## 反模式
- 不要把文档描述直接当成实现证据。
- 不要把“当前实现”和“目标态设计”写在同一段里却不做区分。
- 不要同时批量修改多份文档而不说明它们分别描述的是现状还是规划。

## 备注
- 当前最重要的冲突点是：`/api/v1`、MySQL、邮箱登录、Web/iOS/admin 既有实现假设。
- 非核心设计文档（安装、自动化、协作手册、工作记录）应视为历史/运维资料，不要当产品事实来源。
