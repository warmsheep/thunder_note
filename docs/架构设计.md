# 架构设计

## 文档定位
本文档同时描述**当前态架构**与**目标态架构**。阅读时不要把目标态误当成已实现。

## 当前态架构
### 仓库结构
- 后端：`thunder-note-server/`
- Android：`thunder-note-android/`
- 原型：`thunder-note-prototype.html`
- 文档：`docs/`

### 当前系统形态
- 服务端为 Spring Boot 模块化分包后端
- 客户端当前**真实落地两套**：Android Java 客户端、Web 用户端 v1
- Web 用户端 v1（D1-W0~W19 + W12 + W13）已位于 `thunder_note_server/frontend/`，由同一个 Spring Boot 服务在 `/` 承载 SPA、在 `/api/**` 提供 API
- iOS、管理后台仍属于远期规划，未落地
- HTML 原型承担交互验证角色，不代表生产实现

### 当前 Web 状态
- **已落地：** Web 用户端 v1 位于 `thunder_note_server/frontend/`，技术栈 Vue 3 + Vite + Pinia + Vue Router + Axios + Vitest。
- **承载方式：** 同一个 Spring Boot jar 承担两件事 ——
  - `/api/**` 提供 Android + Web 共用 API
  - `/`、`/index.html`、`/assets/**`、SPA 内部路由（`/login` `/notes` 等）由 `WebStaticResourceConfig` + `SpaFallbackResolver` 处理
- **共享 API 契约：** Web 端**完全复用** `/api/...` 当前实现，未新增任何 Web 专用前缀；路径与 HTTP 方法由 `ControllerHttpMethodContractTest`（10 项）锁住。
- **安全边界：** 由 `SecurityConfig` 强制 `/api/**` + `/actuator/**` 鉴权，其他路径 permitAll；测试 `WebStaticResourceIntegrationTest`（11 项）守关。
- **构建产物：** Vite build 输出到 `src/main/resources/static/web/`，被 jar 直接打包；构建后插件自动同步到 `target/classes/static/web/` 兼容 IDE 增量同步。
- **Web 不适用项：** 同步 / 待同步列表 / 手动同步、手势锁本地解锁、系统分享接收、视频压缩、服务端 BaseURL 切换、调试日志查看页（详见 `完整开发计划.md` § D1.6 "Web 不适用项"）。Web 已实现录音/语音消息与快速捕获入口，不再列入不做项。
- **构建与部署：** 详见 `Web构建与部署.md`。
- **手工回归清单：** 详见 `Web手工回归清单.md`。

### 当前客户端架构
- 当前 Android Java 客户端以 Activity / Fragment + ViewBinding + ViewModel 为主
- 当前 Java 网络基础层使用 Retrofit + OkHttp
- 当前 Java Token 通过 `EncryptedSharedPreferences` 保存
- 当前 Java `auth / flashnote / chat` 已有可编译主链
- 当前 Java `favorite` 已接真实收藏数据；`collection` 已接真实数据；`profile` 当前提供 sync / file / logout 基础操作面

## 目标态架构
### 目标系统范围
- 后端 + Android + Web + iOS + 管理后台
- 多端共享统一的数据模型与同步协议
- 搜索、收藏，系统信息、后台管理等扩展模块逐步补齐

### 目标设计原则
- 服务端继续保持模块化单体方向
- 新 Andr已落地两套客户端：Android Java（`thunder-note-android/`）+ 客户端 v1（`thunder_note_server/frontend/`）；一按可维护的 Jav仍为远期规划，无a 分层
- 构组织 v1 技术栈是 Vue 3 +Pinia**不是**旧文档曾出现的 React
- Web 用户端首期采用后端同仓同服务承载，优先保证与 Android 共享 API 契约，而不是另起一套服务端
- 当前态、目标态、原型设计必须分文档或分章节明确标注

## 已知架构漂移
- 旧文档中 MySQL、React、Elasticsearch、WebSocket 等表述已经不再代表当前主线方案
- 当前 API 实际路径为 `/api/...`，不是 `/api/v1/...`
- 当前真实仓库并没有 Web、iOS、admin 代码目录；Web 已进入后续计划，但仍未落地为真实代码

## 维护规则

- 目标态架构可以保留，但必须明确标注"尚未实现"
- 当旧设计整体失真时，优先重写当前态章节，不在旧文上做碎片式修补
