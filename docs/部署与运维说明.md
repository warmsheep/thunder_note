# 部署与运维说明

## 文档定位

本文档替代旧版部署与运维说明，描述当前推荐的内网 Linux 服务器部署方式。

当前推荐方案：

- Web 前端先构建为静态资源。
- Spring Boot 后端容器承载 Web 静态资源与 `/api/...` 接口。
- PostgreSQL、Redis、MinIO 与后端一起通过 Docker Compose 部署在同一台内网服务器。
- Android、Web 浏览器统一访问 `http://服务器内网IP:8080/`。

本文档以 `CentOS + 已安装 Docker` 为默认目标环境。

## 当前部署事实

### 代码位置

主要部署目录：

```text
/opt/thunder_note
```

后端与 Web 部署入口：

```text
/opt/thunder_note/thunder_note_server
```

### 服务组成

`thunder_note_server/docker-compose.yml` 当前会启动：

- `postgres`：PostgreSQL 主数据库。
- `redis`：缓存与 refresh token 会话存储。
- `minio`：对象存储。
- `minio-init`：一次性初始化 MinIO bucket。
- `server`：Spring Boot 后端，同时承载 Web 静态资源。

### 默认端口

| 服务 | 宿主机端口 | 说明 |
|------|------------|------|
| Web / API | `8080` | 浏览器和 Android 主入口 |
| PostgreSQL | `15432` | 数据库调试入口，长期运行建议仅内网或本机可访问 |
| Redis | `6379` | 长期运行建议仅内网或本机可访问 |
| MinIO API | `9000` | 文件对象存储 API |
| MinIO Console | `9001` | MinIO 管理控制台 |

端口规则：

- `SERVER_HOST_PORT` 是宿主机对外暴露端口，浏览器和 Android 访问这个端口。
- 后端容器内 Spring Boot 固定监听 `8080`，不要在 `.env` 中配置 `SERVER_PORT`。
- `POSTGRES_HOST_PORT` 是宿主机访问 PostgreSQL 的端口；后端容器与 PostgreSQL 容器互连时固定使用 `postgres:5432`。
- 因此日志中出现 `jdbc:postgresql://postgres:5432/thunder_note` 是 Docker Compose 内部网络的正常现象，不代表宿主机 `POSTGRES_HOST_PORT=15432` 没生效。

### 关键配置来源

运行配置优先通过 `thunder_note_server/.env` 注入，模板为：

```text
thunder_note_server/.env.docker.example
```

关键变量：

- `SERVER_HOST_PORT`
- `NOTE_JWT_SECRET`
- `NOTE_CORS_ORIGINS`
- `NOTE_LOG_LEVEL`
- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_HOST_PORT`
- `REDIS_HOST_PORT`
- `MINIO_ROOT_USER`
- `MINIO_ROOT_PASSWORD`
- `MINIO_BUCKET`
- `MINIO_API_HOST_PORT`
- `MINIO_CONSOLE_HOST_PORT`

## 首次部署流程

### 1. 检查 Docker

```bash
docker version
docker compose version
```

如果没有 `docker compose`，CentOS 上优先安装 Docker Compose v2 插件；若环境只能使用旧版 `docker-compose`，可临时将命令中的 `docker compose` 替换为 `docker-compose`。

### 2. 准备目录

```bash
sudo mkdir -p /opt/thunder_note
sudo chown -R $USER:$USER /opt/thunder_note
```

### 3. 放置代码

如果服务器可访问 Git 仓库：

```bash
cd /opt
git clone 你的仓库地址 thunder_note
```

如果服务器不能访问 Git，可在开发机打包后上传：

```bash
cd /Users/warmsheep/Git
tar -czf thunder_note.tar.gz thunder_note
scp thunder_note.tar.gz 用户名@服务器内网IP:/opt/
```

服务器解压：

```bash
cd /opt
tar -xzf thunder_note.tar.gz
```

### 4. 构建 Web 静态资源

进入后端目录：

```bash
cd /opt/thunder_note/thunder_note_server
```

推荐使用 Node Docker 镜像构建，避免在 CentOS 上额外安装 Node：

```bash
docker run --rm -v "$PWD":/work -w /work/frontend node:20-alpine sh -lc "npm ci && npm run build"
```

构建后确认存在：

```bash
ls src/main/resources/static/web
```

应至少看到：

```text
index.html
assets
```

### 5. 创建 `.env`

```bash
cd /opt/thunder_note/thunder_note_server
cp .env.docker.example .env
```

生成 JWT 密钥：

```bash
openssl rand -base64 48
```

编辑 `.env`：

```bash
vi .env
```

内网部署示例：

```env
SERVER_HOST_PORT=8080
NOTE_JWT_SECRET=替换为openssl生成的随机字符串
NOTE_CORS_ORIGINS=http://服务器内网IP:8080
NOTE_LOG_LEVEL=info
NOTE_REDIS_DATABASE=0

POSTGRES_DB=thunder_note
POSTGRES_USER=postgres
POSTGRES_PASSWORD=替换为强密码
POSTGRES_HOST_PORT=15432

REDIS_HOST_PORT=6379

MINIO_ROOT_USER=thundernote
MINIO_ROOT_PASSWORD=替换为强密码
MINIO_BUCKET=thunder-note
MINIO_API_HOST_PORT=9000
MINIO_CONSOLE_HOST_PORT=9001
```

如果希望 Web / API 从宿主机 `28080` 对外访问，应配置：

```env
SERVER_HOST_PORT=28080
NOTE_CORS_ORIGINS=http://服务器内网IP:28080
```

不要配置 `SERVER_PORT=28080`。该变量会改变 Spring Boot 容器内监听端口，导致 Docker 端口映射和健康检查仍访问容器 `8080` 时出现 `Connection reset by peer`。

安全要求：

- `NOTE_JWT_SECRET` 必须替换默认值，部署后不要随意变更。
- `POSTGRES_PASSWORD` 不要使用默认 `postgres`。
- `MINIO_ROOT_PASSWORD` 不要使用默认 `minioadmin`。
- `.env` 不应提交到 Git。

### 6. 启动服务

```bash
cd /opt/thunder_note/thunder_note_server
docker compose up -d --build
```

查看状态：

```bash
docker compose ps
```

查看后端日志：

```bash
docker compose logs -f server
```

`minio-init` 执行完成后退出属于正常现象。

### 7. 验证服务

服务器本机验证：

```bash
curl http://localhost:8080/actuator/health
```

内网其他机器验证：

```bash
curl http://服务器内网IP:8080/actuator/health
```

如果 `.env` 中配置了 `SERVER_HOST_PORT=28080`，验证命令应改为：

```bash
curl http://localhost:28080/actuator/health
curl http://服务器内网IP:28080/actuator/health
```

浏览器访问：

```text
http://服务器内网IP:8080/
```

如果 `.env` 中配置了 `SERVER_HOST_PORT=28080`，浏览器访问：

```text
http://服务器内网IP:28080/
```

MinIO 控制台：

```text
http://服务器内网IP:9001/
```

Android 客户端自托管服务器地址：

```text
http://服务器内网IP:8080/
```

如果 `.env` 中配置了 `SERVER_HOST_PORT=28080`，Android 客户端自托管服务器地址：

```text
http://服务器内网IP:28080/
```

## CentOS 防火墙

查看防火墙状态：

```bash
sudo firewall-cmd --state
```

开放 Web / API 端口：

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

如果 `.env` 中配置了 `SERVER_HOST_PORT=28080`，开放端口应改为：

```bash
sudo firewall-cmd --permanent --add-port=28080/tcp
sudo firewall-cmd --reload
```

如需访问 MinIO 控制台：

```bash
sudo firewall-cmd --permanent --add-port=9001/tcp
sudo firewall-cmd --reload
```

长期运行建议：

- `8080` 对内网客户端开放。
- `9001` 仅对管理员开放。
- `15432`、`6379`、`9000` 不建议对普通客户端开放。

## 常用运维命令

### 查看容器状态

```bash
cd /opt/thunder_note/thunder_note_server
docker compose ps
```

### 查看日志

```bash
docker compose logs -f server
docker compose logs -f postgres
docker compose logs -f redis
docker compose logs -f minio
```

### 停止服务

```bash
docker compose down
```

### 删除服务和数据卷

以下命令会删除 PostgreSQL、Redis、MinIO 数据卷，除非明确要清空环境，否则不要执行：

```bash
docker compose down -v
```

## 数据备份

### PostgreSQL 备份

```bash
cd /opt/thunder_note/thunder_note_server
docker exec thunder-note-postgres pg_dump -U postgres thunder_note > thunder_note_backup.sql
```

### MinIO 数据

MinIO 文件保存在 Docker volume `thunder-note-minio-data` 中。正式使用后应定期备份该 volume，或使用 MinIO Client 对 bucket 做镜像备份。

### Redis 数据

Redis 当前开启 AOF，并使用 Docker volume `thunder-note-redis-data` 持久化。refresh token 会话依赖 Redis，清空 Redis 会导致客户端需要重新登录。

## 故障排查

### 后端启动失败

```bash
cd /opt/thunder_note/thunder_note_server
docker compose ps
docker compose logs --tail=200 server
```

### 数据库启动失败

```bash
docker compose logs --tail=200 postgres
```

### Web 打不开但健康检查正常

检查 Web 静态资源：

```bash
ls -la src/main/resources/static/web
docker compose logs --tail=200 server
```

如果缺少 `index.html`，重新构建 Web：

```bash
docker run --rm -v "$PWD":/work -w /work/frontend node:20-alpine sh -lc "npm ci && npm run build"
docker compose up -d --build server
```

### 外部机器访问不了

检查：

- 服务器 IP 是否正确。
- `firewalld` 是否开放 `8080/tcp`。
- Docker 容器是否运行。
- 浏览器访问的地址是否为 `http://服务器内网IP:8080/`。
- `.env` 是否误写了 `SERVER_PORT=28080`；外部端口应使用 `SERVER_HOST_PORT=28080`。

## 维护规则

- 配置项、端口、依赖服务、部署方式发生变化时，必须同步更新本文档。
- 不要把 `.env`、数据库备份、MinIO 密钥、JWT 密钥提交到 Git。
- 前端改动上线前必须先构建 Web 静态资源，再重新构建后端镜像。
- 后端 schema 变更由 Flyway 在应用启动时自动迁移；上线前必须先在测试环境验证迁移脚本。
