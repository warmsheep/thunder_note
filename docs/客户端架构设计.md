# 客户端架构设计

## 文档定位
本文档分为三部分：**当前 Android 架构**、**当前 Web v1 架构**、**未来多端目标态（iOS / 管理后台）**。当前仓库已落地 Android Java 客户端与 Web 用户端 v1；iOS 已创建独立 Git 目录 `thunder_note_ios/`，但尚无 Xcode/SwiftUI 客户端工程；管理后台仍为远期规划。

## 当前 Android 架构（Java 客户端主线）
### 当前真实分层
```
ui/            -> Activity、Fragment、ViewModel
data/          -> Retrofit、DTO、内存仓储/后续本地仓储
core/          -> Token、网络、应用级装配
```

### 当前真实能力
- Java 版 Splash / Login / Register 已落地
- Java 版 Main 底部五 tab 壳层已落地（闪记/合集/联系人/收藏/我的）
- Java 版 FlashNote 列表页、Chat 页面、Collection 页面已接入真实后端主链
- Java 版 Contact 页面已接联系人列表、好友请求列表、请求红点、联系人搜索与添加好友、滑动删除联系人，并可打开联系人会话；联系人列表现展示最新一条消息，且会补入“等待对方同意”的挂起联系人
- Java 版 Contact 聊天消息已按 `senderId==当前用户` 区分左右气泡：我方右侧、对方左侧白底
- `TokenManager`、`ApiClient`、Auth / FlashNote / Message / Collection / Sync / File 基础仓储已落地
- 登录页当前已补“官方服务器 / 自托管服务器”入口；Android v1 按**单站冷切换**工作，切换服务器地址后会清理当前站点登录态并回到登录页。服务器地址入口当前仅保留在登录页，不再出现在设置页。
- Android 当前已补手势锁本地主链：支持本地设置/修改、冷启动门禁、超时回前台再次校验、关闭手势锁，以及服务端密文备份接口；当前定位仍是**本地二次解锁**，不是独立登录方式。
- 登录页当前会在成功消费本次真实登录结果后清空旧 `loginResponse`，避免切站或回到登录页时误复用旧登录成功态；登录/注册成功后会重建依赖当前用户身份的 session-scoped repositories，避免首次登录后列表仍绑定到 `userId=-1` 的旧观察源。
- 手势设置页当前已统一“保存手势 / 重新绘制”按钮的文字样式与颜色，并把手势绘制区域调整为随页面高度自适应填充的主内容区，避免页面中下部过空。

### 当前仍偏骨架/模拟的部分
- Favorite 已接真实收藏链路；当前支持从聊天页长按消息加入收藏，并在 Favorite tab 查看/移除
- Profile 当前仍偏操作台式，但已补“从头像入口进入独立修改个人资料页（昵称/简介/头像预览）并保存返回”主流程
- Java 客户端和后端 DTO / repository 已完成当前 MVP 所需收敛，但仍缺更完整测试与体验打磨

### 当前聊天双模式事实
- 闪记会话：按 `flashNoteId` 聚合消息，保留原有闪记内对话链路
- 联系人会话：按 `peerUserId` 聚合双向消息，复用聊天页的文字/语音/图片/视频/文件发送能力
- 收集箱会话：虚拟 `flashNoteId=-1`，用于闪记列表页快速收集（消息/图片/文件/拍照）
- 闪记页悬浮 `+` 的“消息”入口当前改为独立全页编辑页，提供基础富文本快捷项（粗体/斜体/引用/待办）
- 聊天页当前已支持复合卡片消息：长按消息可进入多选合并，输入标题后调用 `/api/messages/merge` 生成卡片；卡片点击进入 `CardDetailActivity`
- 聊天页工具栏与闪记页悬浮 `+` 菜单当前都已新增“卡片”入口，进入独立卡片编辑页，可创建图片/视频/文件卡片并发送到当前会话或收集箱
- 三种模式共享同一聊天 UI，但在 repository 层按不同会话键分别缓存与分页（联系人会话键已避开与 `-1` 冲突）；当前 `flashNoteId=-1` 已支持与普通闪记一致的发送、删除、分页和草稿链路

## Java Android 客户端（当前主线，仍在补齐）
### 目标原则
- 以 Java 作为客户端主语言
- 优先继承后端契约、产品范围、页面导航范围、经验库中的真实问题
- 架构优先保证：易理解、易调试、易与后端接口对齐

### 必须继承的事实
- 登录语义按 `username`，不是邮箱
- 后端 API 当前真实路径为 `/api/...`
- `AuthRepositoryImpl` 已是当前主线实现；`SyncRepositoryImpl` 也已接真实接口，但同步能力仍停留在最小闭环阶段
- Android 当前网络基址不再只等于编译期 `BuildConfig.BASE_URL`；`ServerConfigStore` 已成为当前服务器地址的运行时事实来源，`ApiClient / TokenAuthenticator / MediaUrlResolver` 已跟随当前服务器配置工作

## 当前 Web v1 架构
### 真实分层
- **位置：** `thunder_note_server/frontend/`，与后端同仓同 jar，Vite build 产物落到 `src/main/resources/static/web/`，Spring Boot 直接托管。
- **技术栈：** Vue 3 + Vite + Pinia + Vue Router + Axios + Vitest。
- **目录：**
  - `src/api/`：API 客户端封装（`client.js` axios 实例 + 各模块 wrapper）
  - `src/stores/`：Pinia stores（auth / chat / flashNotes / collections / favorites / profile / contacts / search 等）
  - `src/views/`：路由级页面（NotesView / ChatView / CollectionsView / FavoritesView / SearchView / ProfileView / ContactsView / ChangePasswordView / LoginView / RegisterView 等）
  - `src/layouts/MainShell.vue`：主壳层，桌面 sidebar + 移动 bottombar
  - `src/components/`：可复用组件（MessageBubble / MediaPreview / ImageLightbox / PdfViewerDialog / TextViewerDialog / MessageComposer / ConfirmDialog / NoteEditDialog / CollectionEditDialog / AuthenticatedAvatar / EmptyState / ErrorState / LoadingState）
  - `src/composables/`：可组合逻辑（`useChatScroll` / `useToast` 等）
  - `src/utils/`：纯函数工具（messageHelpers / fileHelpers / markdownRenderer 等）
  - `src/styles/global.css`：设计 token + 全局焦点环 + 工具类

### 状态与导航
- **登录态：** `auth` store + `apiClient` 拦截器自动注入 token + 401 时自动 refresh；token 持久化由 `tokenStorage` 抽象层处理。
- **路由：** `/login` `/register` `/baseline` 公开；其他统一在 `MainShell` 嵌套路由下；`/chat/:flashNoteId` 是独立顶级路由（不在 MainShell 内）以便 ChatView 自己布局 100vh。
- **错误反馈：** `useToast` composable 统一弹 toast；表单字段校验 + 后端错误信息双层兜底。

### 媒体与文件
- 上传走 `apiClient` POST `/api/files/upload`（multipart）→ 拿 `objectName`
- 下载走 `apiClient` GET `/api/files/download?objectName=...` 返回 blob → `URL.createObjectURL`
- 关键：`apiClient` 不能给 FormData 设默认 Content-Type，否则 multipart boundary 丢失（W17 已修）

### Markdown 与 XSS 防护
- `utils/markdownRenderer.js` 用 `marked` + `DOMPurify` 严格白名单渲染消息正文
- 收藏页与聊天气泡共用同一个 renderer，保证体验与安全策略一致

### 滚动与状态
- `composables/useChatScroll.js` 收口"发送 / loadMore / 新消息追加 / 离开会话 / 进入会话"五个时机
- 离开会话 `onBeforeUnmount` 写 `sessionStorage[tn:chat:scroll:<flashNoteId>]`
- 进入会话优先恢复，没有则滚到底
- Web 端不维护 Room / PendingMessage / 本地同步队列；页面与 API 同源，直接读写服务端事实数据，因此没有“待同步列表 / 手动同步按钮 / 离线同步引擎”这类 Android App 专属职责。

### 测试
- Vitest **269 项**：覆盖 stores / utils / composables / 关键 API 客户端
- 后端契约测试 `ControllerHttpMethodContractTest`（10 项）+ `WebStaticResourceIntegrationTest`（11 项）守 Web 与 Android 共享 API 不漂移

### Web 不适用项
- 同步 / 待同步列表 / 手动同步、手势锁本地解锁、系统分享接收、视频压缩、服务端 BaseURL 切换、调试日志查看页
- 详见 `完整开发计划.md` § D1.6 "Web 不适用项"

#### 分层
```
View (SwiftUI)
   ↓ 观察
ViewModel (@MainActor class, @Observable)
   ↓ 调用
Repository (actor / protocol)
   ↓ 调用
APIClient (URLSession) ←─→ LocalStore (SwiftData / Keychain / FileManager)
```

- View 只描述 UI 与事件，不持有领域状态。
- ViewModel 持有当前页面状态，与 Android `*ViewModel` / Web Pinia store 等价。
- Repository 是真实事实来源，所有 API 调用、本地落库、PendingMessage 入队都在这里。
- APIClient 承担拦截器（鉴权注入、`ApiResponse<T>` 解包、401→refresh）。
- 仓储与 ViewModel 之间通过 `protocol` 抽象，便于注入 mock 测试。

#### 网络层契约
- **BaseURL**：来自 `ServerConfigStore`（官方 / 自托管），不再依赖编译期常量，与 Android `ServerConfigStore + ApiClient` 等价。
- **请求语义**：所有 JSON 读取/写入统一 `POST`，文件下载 `GET`，SSE `GET`。
- **响应包装**：`ApiResponse<T> { code, message, data, timestamp }`，code≠0 抛 `APIError`，401 单独触发 `RefreshActor.refreshIfNeeded()`。
- **错误模型**：对齐 `ErrorCode`（40000 / 40100 / 40300 / 40400 / 50000）。
- **重连**：SSE 走 `URLSession.dataTask` + 自管 `Last-Event-ID`；同步重试用指数退避（与 Android `PendingMessageDispatcher` 等价）。

#### 本地持久化
- **结构化表**（SwiftData / Core Data）与 Android Room 对齐：
  - `FlashNoteLocal`（id / name / description / pinned / archivedAt / updatedAt）
  - `CollectionLocal`
  - `MessageLocal`（含 `conversationKey`、`flashNoteId`、`peerUserId`、`role`、`mediaType` 等字段）
  - `FavoriteLocal`
  - `PendingMessageLocal`（id / conversationKey / payload / retryCount / lastError / createdAt）
- **Keychain**：`accessToken` / `refreshToken` / 手势锁密文 / 服务器配置；`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`，禁止 iCloud 同步。
- **媒体缓存**：`Caches/media/` 下按 objectName 哈希分桶；最大缓存大小可在设置页清理。

#### 会话与状态
- **登录态**：`AuthSession` 单例（`@Observable`），保存当前 user / accessToken；切站 / 登出时同步重置依赖会话的仓储（与 Android `RepositoryStateStore` 等价）。
- **多会话模式**：复用同一 `ChatView`：
  - 闪记会话：`conversationKey = "flash:\(flashNoteId)"`
  - 联系人会话：`conversationKey = "peer:\(peerUserId)"`
  - 收集箱会话：`conversationKey = "flash:-1"`
- **路由**：`NavigationStack` + 顶层 `enum AppRoute`，主壳层 5 tab（闪记 / 合集 / 联系人 / 收藏 / 我的）与 Android `MainShellFragment` 对齐。

#### 同步模型
- **首启**：登录成功后调 `bootstrap` → 落库；与 Android `SyncRepositoryImpl.bootstrap()` 等价。
- **拉取**：`pull` 在 App 启动、回前台、手动同步、SSE 收到 `sync` 事件时触发，落库后用 NotificationCenter 通知各 Repository 刷新本地观察源（对应 Android `MessageRepositoryImpl.refreshLocalConversations()`，参见经验库 75）。
- **推送**：本地发送（消息 / 闪记 / 合集 / 收藏）先写入 `PendingMessageLocal`，由 `SyncEngine`（actor）顺序消费 → 调 `push` → 成功后清队。
- **后台**：`BGTaskScheduler` 注册 `tn.sync.refresh` 任务，与 iOS 后台预算策略协作。
- **SSE**：登录态在线时建立 `EventStreamSession`，解析 `event: sync | message | heartbeat`；断线后用 `Last-Event-ID` 续传。

#### 多媒体与文件
- **拍照 / 选图**：`PhotosPicker`（iOS 16+）。
- **录音**：`AVAudioRecorder` + 自实现波形采样，与 Android `ChatRecordingHelper / VoiceWaveView` 等价。
- **视频**：`AVPlayerViewController`；如启用本地压缩则用 `AVAssetExportSession`。
- **PDF / 文件预览**：`PDFKit` 内嵌 + `QuickLook` 兜底，对应 Android `FilePreviewActivity`。
- **保存 / 外部打开**：`UIDocumentPickerViewController(forExporting:)`、`UIActivityViewController`。
- **系统分享接收**：`ShareExtension` target，把分享进来的文本/图片/文件落到主 App 的 ShareInbox，主 App 启动后自动消费（与 Android `ShareReceiverActivity` 等价）。

#### 安全
- Token / 手势锁密文走 Keychain（device-only），不允许进 `UserDefaults`。
- 手势锁本地校验，**不是独立登录方式**，仅作为二次解锁；与 Android `GestureLock*` 系列对齐。
- 网络层默认 ATS，禁止全局 `NSAllowsArbitraryLoads`；自托管 HTTPS 不可用时由用户在服务器设置页明确开启例外。
- `LocalAuthentication` 用作手势锁忘记后的兜底身份验证选项（生物识别），默认关闭。

#### 与 Android 对齐的额外关键点
- **`ConversationKey` 统一标识**：闪记 `flash:<id>`、联系人 `peer:<userId>`、收集箱 `flash:-1`；与 Android `ConversationKeyUtil` 等价。
- **PendingMessage 模型**：`{ id, conversationKey, clientRequestId(UUID), payload, retryCount, status, lastError, createdAt }`；客户端必须自带 `clientRequestId`，与 Android 一致。
- **Session-scoped Repository 重建**：登录态变化时由 DI 容器重建依赖会话的 Repository / ViewModel，避免观察源绑定到 `userId=-1` 或旧用户；与 Android `clearSessionScopedRepositories` 等价。
- **缓存版本号迁移**：App 启动比对 `cache_clear_version`，跨过阈值时清理图片缓存 / 头像 / `Caches/`；与 Android `clearStaleCacheOnUpgrade` 等价。
- **崩溃捕获**：`NSSetUncaughtExceptionHandler` + signal handler 写入当前 DebugLog 文件，与 Android `DebugLog.installCrashHandler` 等价。
- **Toast 节流 / 网络错误过滤**：`ToastCenter` 提供同 key 2s 内只弹一次；包含网络错误关键字（`network`、`timeout`、`unable to resolve host` 等）的不弹 toast；与 Android `DebugLog.shouldShowToast / isLikelyNetworkIssue` 等价。
- **音频播放互斥**：`AudioPlaybackCoordinator` 通过 NotificationCenter 广播 play 事件，其他正在播放的 player 自动暂停；后台时主动暂停；与 Android `notifyAudioPlay/Pause` 等价。
- **MediaUrlResolver**：把 `objectName` 解析为完整 `/api/files/download?objectName=...` URL，统一图片 / 视频 / 文件 / 头像下载地址；与 Android 同名工具等价。
- **`refreshLocalConversations`**：`pull` 落库后收集涉及 conversationKey，主动重新读取本地 DAO 并刷新各 conversation 的 Observable，避免"消息总数变了但当前会话未刷新"问题（经验 75）。
- **外部 flow 跳过手势锁**：进入 PhotosPicker / 相机 / 文件选择 / Share / 裁剪前打标记，回前台不弹手势锁；与 Android `ExternalFlowGestureUnlockHelper` 等价。
- **`username` scope 隔离本地数据**：手势锁、profile 缓存、avatar 缓存的 key 都按当前 `username` 加前缀，避免跨账户串扰；与 Android `GestureLockManager.scopedKey()` 等价。

#### 与现有事实对齐
- 复用当前 `/api/...` 契约，不另起 `/api/ios/`。
- 登录字段是 `username`，不是 `email`。
- 复用 Android 已统一的接口列表（见 `当前联调契约总表.md`）。
- 任何 API DTO 字段映射，先以后端 controller 与 `当前联调契约总表.md` 为准，再落到 Swift `Codable` 模型。
- Android 当前未消费 SSE (`GET /api/messages/stream`)；iOS 首期可不接入，与 Android 节奏同步推进。
- Android 当前未接 FCM 推送通知；iOS 首期同样不接 APNs，避免单端能力领先。

### 设计原则
- 多端统一产品语义与数据模型
- 当前实现与目标态设计必须分开描述
- 未落地端只写"规划"，不写成"已有实现"

## 维护规则
- Android 相关结论优先以当前代码为准
- Web / iOS 相关结论优先以当前计划和目标态文档为准；Web 已落地后应优先以 `thunder_note_server/` 中真实资源、路由和 API 调用为准；iOS 后续一旦建立工程，应优先以 `thunder_note_ios/` 中真实代码为准
- 如果 Android API 声明与后端 controller 不一致，先以后端 controller 为准
- 如果 Web API 调用与后端 controller 不一致，同样先以后端 controller 为准，并同步更新本文件与 `API接口设计.md`
